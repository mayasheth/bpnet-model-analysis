MultiModalBPNet architecture

A BPNet variant that jointly uses DNA sequence and base-pair-resolution chromatin accessibility to predict stranded p300 ChIP-seq signal. Defined in scripts/multimodal_bpnet.py; trained via scripts/train_multimodal_bpnet.py.

Why "middle fusion"? The two modalities each get their own initial convolution before being merged, rather than concatenating the raw inputs (early fusion) or combining only at the output (late fusion). This lets each branch learn modality-specific low-level features while sharing representational capacity in the deeper layers where sequence and accessibility context interact.

Input encoding

Channel 0–3: DNA sequence

One-hot encoding over {A, C, G, T}. N bases and lowercase are encoded as all-zero vectors. The input window is 2114 bp centered on each peak summit (or region midpoint for negatives). The extra 2 × 557 bp beyond the 1000 bp output window is consumed by the trimming from dilated convolutions.

Channel 4: chromatin accessibility

Raw accessibility values (ATAC Tn5 cut counts or DNase cut counts at 1 bp resolution) are transformed before input: log1p → z-score (subtract mean, divide by standard deviation). Mean and standard deviation are computed from training peaks only and reused for validation and negatives to prevent data leakage. 

acc_normalized = (log1p(clip(acc, 0)) - mean) / std
Tuning the accessibility input The current normalization is simple and has no learnable parameters. Alternatives worth exploring: (1) bias correction of the accessibility signal to account for Tn5/DNase sequence preference before training; (2) learned normalization (e.g., a BatchNorm or LayerNorm on the accessibility channel); (3) using a smoothed accessibility signal (e.g., Gaussian-smoothed at ~50 bp) rather than raw 1 bp cuts, which may reduce noise.

Reverse complement augmentation

During training, each example is randomly reverse-complemented with probability 0.5:

SignalTransformationReason
DNA (ch 0–3) Flip channel order (T↔A, G↔C) AND reverse positions Standard DNA reverse complement
Accessibility (ch 4) Reverse positions only Accessibility is unstranded; no channel flip needed
Signal target (ch 0–1) Swap plus/minus channels AND reverse positions Plus strand becomes minus strand under RC

Layer-by-layer description

Initial convolutions (separate per modality)

ParameterDefaultNotes / tuning
n_filters64 Filters for the sequence branch initial conv. Standard BPNet uses 64. Increasing (e.g. 128, 256) adds capacity but slows training. Decreasing reduces overfitting on small datasets.
n_acc_filters8 Filters for the accessibility branch initial conv. Kept small (8 = 12.5% of sequence capacity) to reflect that accessibility is a 1D scalar signal rather than a 4-letter alphabet. Tuning: increase to 16–32 if you suspect the accessibility branch is a bottleneck; decrease to 4 if overfitting.
kernel_size21 Same for both branches. Captures ±10 bp local context in the initial projection. Not exposed as an argument; change in multimodal_bpnet.py if needed.

After each initial convolution, a ReLU activation is applied. No batch normalization is used (consistent with standard BPNet; BN can interfere with the MNLL profile loss).

Concatenation (middle fusion)

The two branches are concatenated along the channel dimension: (N, 64, L) cat (N, 8, L) → (N, 72, L). All subsequent layers operate on this merged representation. The channel imbalance (64 vs 8) implicitly weights sequence more heavily than accessibility — intentional, since sequence is the primary signal.

Dilated residual stack

ParameterDefaultNotes / tuning
n_layers8 Number of dilated Conv1d layers. Dilations are 21…28 = 2, 4, 8, 16, 32, 64, 128, 256. Receptive field = 47 + 2×(2+4+8+16+32+64+128+256) = 47 + 1020 = 1067 bp. Matches standard BPNet. Increasing to 10 layers extends to 4139 bp receptive field but adds memory cost.
kernel_size3 Fixed for residual convolutions. Each layer's actual receptive field contribution is (3−1)×dilation. Not exposed as argument.

Each residual layer computes: X = X + ReLU(Conv1d(X, dilation=2^i)). The channel count stays constant at n_filters + n_acc_filters = 72 throughout the stack.

Trimming Because dilated convolutions expand the receptive field, the edges of the output are less well-predicted. BPNet trims both ends of the sequence before reading profile predictions. Trimming = 47 + sum(21…28) = 557 bp per side. With an input of 2114 bp, the output profile is 2114 − 2×557 = 1000 bp, matching the target window.

Profile head

A final Conv1d with kernel size 75 (padding 37) maps from (N, 72, 2114) to (N, 2, 2114), then the trimmed region (N, 2, 1000) is returned as logits. The two output channels correspond to the plus and minus strand ChIP-seq profiles. A softmax is applied implicitly during the MNLL loss (not in the forward pass).

Profile head kernel size (75 bp) This large kernel integrates information across ±37 bp and captures the typical ~150 bp nucleosome-free region shape. If modeling a different assay with sharper or broader footprints, this should be adjusted. Smaller values (e.g. 25) produce sharper predictions; larger (e.g. 151) smooth them more.

Counts head

The merged representation is mean-pooled across the output window (positions 557–1557, i.e. the 1000 bp center ± 37 bp buffer on each side), then passed through a single linear layer to predict log total counts: (N, 72) → (N, 1). This is used to predict the scalar total ChIP-seq signal at each region.

Loss function

The model is trained with a two-term mixed loss, following BPNet convention: 

loss = MNLL(profile_logits, signal_counts)    # profile shape
     + count_loss_weight × log1pMSE(log_counts_pred, log_counts_true)  # total counts
TermFunctionWhat it learns
Profile loss Multinomial negative log-likelihood (MNLL) Shape of the ChIP-seq profile — where reads pile up within the window, independent of total count
Counts loss MSE on log1p-transformed total counts Total signal magnitude — whether the region is a strong or weak peak
ParameterDefaultNotes / tuning
count_loss_weight1.0 Relative weight of the counts term. Increasing (e.g. 2–5) pushes the model to prioritize count prediction at the possible expense of profile shape. Decreasing (e.g. 0.1–0.5) prioritizes shape. Standard BPNet uses 1.0. For accessibility models (ChromBPNet), lower values are sometimes used because profile shape is more informative than total counts.
Why MNLL for the profile? ChIP-seq read counts at each position follow a multinomial distribution given a fixed total read count. MNLL loss treats the profile logits as unnormalized log-probabilities of a multinomial, making it a principled probabilistic loss for count data with variable depth across regions. This is preferable to MSE on profiles because it is scale-invariant (the shape, not the absolute level, is what matters for profile loss).

Training procedure

Data sampling

Each epoch iterates over peaks, with negatives (GC-matched genomic regions) randomly interspersed.

ParameterDefaultNotes / tuning
negative_ratio0.1 Fraction of each batch that is negatives (≈9.1% of samples). Higher values increase the model's specificity (fewer false positives on non-peak regions) at the cost of slower convergence on positives. Standard range: 0.05–0.2.
max_jitter50 bp Peak examples are randomly shifted by ±50 bp around the summit during training. This augmentation exposes the model to varied centering offsets and improves positional robustness. Not applied to negatives. Set to 0 to disable.
Negative sampling strategy Negatives are GC-matched regions drawn from genomewide_gc_stride_1000_flank_size_1057.gc.bed. GC-matching prevents the model from simply learning GC content as a proxy for p300 binding. Each epoch, negatives are sampled uniformly at random; peaks are shuffled and cycled so that all peaks are seen once per epoch before repeating.

Cross-validation strategy

5-fold cross-validation using chromosome-based splits (fold JSONs in reference/fold{0–4}.json). Each fold holds out 2–3 chromosomes for validation and trains on the remaining chromosomes. The model is saved only when validation loss improves.

Known limitation: train/test leakage Chromosome-based splits do not account for sequence similarity across chromosomes. Regions with similar sequence on different chromosomes can effectively leak between train and test sets. A sequence-similarity-aware splitting strategy (e.g., hashFrag) would give a less optimistic performance estimate.

Model selection and outputs

At each epoch, if the combined validation loss (profile MNLL + count MSE) improves, the full model object is serialized to multimodal_bpnet.torch (PyTorch save). The final-epoch model is additionally saved as multimodal_bpnet.final.torch. Prefer the .torch (best) file for inference. Accessibility normalization statistics (mean, std) are saved to acc_normalization_stats.json and must be reused for inference.

Key design question The model tests whether providing base-pair-resolution accessibility as an explicit input improves p300 prediction beyond what sequence alone can achieve. If the multimodal model significantly outperforms the sequence-only model (especially on regions that are accessible but not p300-bound, or p300-bound but in unusual chromatin contexts), it suggests that chromatin state contains predictive information not encoded in the DNA sequence itself.
