## Key decisions

- **`--profile-loss-weight 0.0561`** for the multi-task arm, the measured H3K27ac/DNase
  per-window depth ratio. MNLL scales with read depth, so an unweighted target swap to a
  17.8x deeper track divides the effective count weight by ~18 and makes a loss on counts
  uninterpretable. Default stays 1.0 so no earlier run moves.
- **The DNase panel's floor is each target's own DNase-ONLY model**, which meant training
  two that did not exist. Every prior accessibility-only model used ATAC, and THP-1 has no
  ATAC, so the three cells would have had floors on different assays in a panel about the
  DNase input. **General rule now recorded: a floor must use the same assay as the model it
  bounds.**
- **Depth-match on genome-wide total, not per-window mean.** Per-window means are computed
  over each cell type's own DNase-derived elements, and those calls are depth-dependent, so
  matching on them is partly circular.
- **5 MB git limit with a path allowlist for the report HTMLs.** The reports are the
  deliverable and grow a megabyte at a time, so a pure size gate would eventually block
  them. Hook source of truth is
  `~/Documents/my-scripts-for-me/git-hooks/pre-commit-filesize`.
- **Do not push as you go.** Maya reviews batches; prompt her when a coherent set exists.
- **Each ABC arm family gets its own results dir.** `4.5 --copy-peaks` re-stamps Peaks,
  and doing that inside a finished run makes its arms look stale to Snakemake.

## Lessons learned and gotchas

- **Changing the loss changes the stopping rule.** Every arm stops on its own validation
  loss, so any loss change alters training length and a comparison against an early-stopped
  baseline cannot attribute the result. Recorded in `.living/learnings.md` with the three
  earlier arms that lacked this control (`1.19` asym, the residual objective, the `clw`
  sweep).
- **The benchmark and top-quintile Pearson disagree in both directions.** F-004: Pearson
  gains that moved nothing downstream. F-019: a change worth +0.0000 on Pearson worth
  +0.0086 downstream. Never infer one from the other.
- **`owners` auto-requeues preempted jobs.** Resubmitting by hand creates two jobs writing
  the same output directory. Check `squeue` before resubmitting.
- **Gate waits on consumed artefacts, never on a driver's exit code.** The ABC driver exits
  COMPLETED with rules failed, and `squeue | grep -q` cannot tell an empty queue from a
  dead socket.
- **Unpaired per-predictor CIs cannot resolve anything here.** They run +/-0.05 while the
  effects are 0.01-0.08. Always `4.17` for AUPRC, `2.38`/`2.15 --pair` for fold metrics.
- **Counting paths are a real confound in ABC arms.** Read files go through
  `count_bam`/`count_tagalign`, bigwigs through `count_bigwig`. `4.6` now records which
  pairs are legitimate; the observed-H3K27ac anchor is reference only.

## Both downstream wins are IN-CELL, and transfer is nearly untested

F-018 and F-019 are K562-trained, predicting on K562 regions, scored against K562 CRISPR
data. Neither involves transfer. The CRISPR benchmark is K562-only, which is also why the
THP-1 and GM12878 ABC arms are blocked on benchmark availability rather than compute.

**Transfer has been benchmarked exactly once, in F-004**: two GM12878-trained ATAC-input
models applied to K562 scored **0.455 and 0.452 against a 0.457 floor**, i.e. at or below
it. Two holes in that test: those arms were early-stopped (F-019 suggests the budget
matters downstream) and they were judged on unpaired per-predictor CIs, which F-008 later
showed cannot resolve differences of this size. **No DNase-input or multi-task transferred
arm has ever been benchmarked.**

| scenario | evidence |
|---|---|
| in-cell, ATAC at inference | clears the floor, +0.0208 to +0.0255 (F-019) |
| in-cell, DNase at inference | clears it by more, +0.0839 (F-018) |
| transferred, ATAC at inference | 0.455/0.452 against a 0.457 floor, but early-stopped and unpaired (F-004) |
| transferred, DNase at inference | never tested |

F-016 and F-017 found no model beating an assay-matched floor in six directions on Pearson,
so a transferred ABC arm should be expected to fail. But the benchmark has disagreed with
Pearson three times now (F-004, F-018, F-019), so do not treat that as settled.

## Next steps

1. **Isolate the 100-epoch effect from run-to-run variance before adopting it.**
   **This is the weakness in F-019 and it was found after the finding was written.** `1.29`
   is a SEPARATE training run from the baseline, not a continuation, and cuDNN convolution
   is not bit-reproducible across nodes (decision 2026-09-03 is why the regression gates use
   a tolerance). So +0.0086 [+0.0005, +0.0175] conflates the epoch budget with run variance,
   at one run per condition. The only evidence isolating the budget: within the 100-epoch
   run the best validation checkpoint landed at epoch 40, 38 and 47 in folds 1, 2 and 4,
   later than where the early-stopped run ended there.
   **Cleanest test, nearly free:** score the SAME 100-epoch run's epoch-35 checkpoint against
   its epoch-100 checkpoint, which removes run variance entirely. Failing that, repeat both
   conditions at two or three seeds. Nothing should rest on "train longer" until one of
   these is done.

2. **Re-test F-004's two transfer arms with the paired bootstrap.** Costs nothing: the ABC
   outputs already exist in the July/September runs, so it is one `4.17` call. It would say
   whether the one transferred arm ever benchmarked was genuinely at the floor or merely
   unresolvable on the unpaired CIs it was judged with.
3. **Re-measure dynamic range for the DNase-input prediction** (`4.9`/`4.10` against
   `predk27ac_k562_dnase.bw`). F-004 named compressed spread on regulated-pair regions as
   the mechanism (p99/p50 4.03 against 6.00 observed). F-018 never tested whether the
   DNase-input model fixed it, so the mechanism of the project's best downstream result is

4. **Second thinning seed for F-017.** One draw at seed 0 currently carries the transfer
